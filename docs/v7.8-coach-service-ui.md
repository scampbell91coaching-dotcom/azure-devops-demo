# V7.8 coach service management UI

## Coach experience

The athlete detail page now opens with a concise **Client services** panel. It shows the effective state for:

- training coaching: Yes / No;
- nutrition coaching: Yes / No;
- meet-day support: Yes / No;
- video review: None / Limited / Included.

Each service shows who set the effective value and when it took effect. When a future-dated decision exists, the next scheduled value, date, and coach are shown immediately below the current state. Coaches can apply changes now or choose an effective date.

Disabling a service prompts for confirmation and explicitly says that existing programmes, check-ins, reviews, and notes remain available. The same retention statement remains visible beside the save action. The controls collapse to one column and the save action becomes full width on small screens.

## Data and resolution

`client_service_changes` is an append-only decision log. A new row records the athlete, service, selected value, effective date/time, creation time, and coach. Updating an entitlement never deletes historical service decisions or athlete content.

For each service, the effective state is the latest decision whose `effective_at` is not in the future. The earliest future decision is presented as the scheduled change. Athletes without recorded decisions use explicit service defaults: training coaching Yes; nutrition coaching No; meet-day support No; video review None.

This model is deliberately separate from check-in workflow settings. A coaching entitlement and whether a particular check-in workflow is enabled are different concerns.

## Scope boundaries

The surface contains no price, payment, invoice, subscription, provider, or billing-plan concepts. It does not call an external provider and does not change infrastructure. The single schema migration is required to retain provenance, future decisions, and history safely.

## Verification

Focused Flask tests cover default/effective resolution, provenance, a scheduled change, validated coach updates, append-only retention, and invalid states. Playwright coverage exercises the panel at a 390px viewport, persists a video-review change, verifies provenance, and checks horizontal overflow.
