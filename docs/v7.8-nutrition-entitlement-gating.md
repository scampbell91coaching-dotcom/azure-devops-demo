# V7.8 nutrition entitlement gating

## Policy

`AthleteCheckinSettings.nutrition_enabled` is the migration-free source of truth
for active nutrition coaching. The policy is exposed by
`portal.services.nutrition_entitlements.nutrition_coaching_enabled`; routes and
dashboard services consume that policy rather than reinterpreting the database
field in templates.

- An explicit `false` disables active nutrition coaching.
- An explicit `true` preserves all existing workflows.
- A missing settings row is treated as enabled for legacy clients created before
  entitlement persistence. Newly created athletes receive an explicit disabled
  row, so this fallback does not grant new clients nutrition access.
- `workflow_active` continues to control the weekly check-in schedule as a whole;
  it is not a nutrition entitlement.

## Surface inventory and behaviour

| Surface | Disabled behaviour |
| --- | --- |
| Athlete desktop/mobile nutrition navigation | Hidden |
| Athlete dashboard nutrition card and nutrition trend | Hidden; nutrition data is not used for athlete bodyweight/response projections |
| Dedicated nutrition check-in GET/POST | `403` after normal athlete authorization/scoping |
| MyFitnessPal import preview/commit/disconnect and index | `403`; no import mutation or destructive disconnect is available |
| Weekly check-in nutrition module | Omitted by the existing settings-driven form and submission service |
| Weekly prompt/reminder | Training-only prompts remain if training is enabled; nutrition alone cannot make a disabled athlete due |
| Coach daily review queue | Unreviewed dedicated nutrition submissions for disabled athletes are excluded |
| Coach athlete dashboard | Historical nutrition check-ins and imported summaries remain visible, labelled `History only`; add/import/review controls are removed |
| Coach nutrition overview | Historical aggregate records remain visible; it is a reporting surface, not an active task queue |
| Macro prescriptions and meal plans | Domain-only services have no routes, persistence, reminders, or task generation in V7.8; no active action is exposed |

The application currently has no notification/reminder delivery subsystem beyond
the computed weekly due prompt, and no persisted macro/meal-plan assignment
workflow. Those paths therefore require no additional runtime gate in this
release.

## Authorization and history

Entitlement checks are additive to existing identity and athlete-scope checks.
They do not grant access to another athlete and do not delete or rewrite any
nutrition check-in, weekly check-in, import, connection, or bodyweight record.
Coach historical visibility is retained as read-only after disablement. Re-enable
the entitlement to resume review responses, imports, and new submissions.

## Verification

Focused Python coverage verifies explicit disablement, direct-route rejection,
review-queue suppression, read-only coach history, and the legacy missing-row
fallback. Playwright coverage toggles an entitlement, verifies the coach surface
and direct route, and restores the fixture in a `finally` block.
