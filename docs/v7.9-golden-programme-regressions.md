# V7.9 golden programme regressions

## Purpose

The V7.9 golden corpus protects representative programme structure at the Block
Factory preview-to-persistence boundary. It is intentionally a set of field-level
assertions, not an HTML or serialized-object snapshot. Presentation copy, IDs,
timestamps, and proposal signatures may change without rewriting the corpus.

No production selection policy is introduced or changed by this work.

## Representative sources

The corpus is based on the programme shapes already present in the repository:

- `platform-portal/data/traditional_strength_intelligence.json` supplies the
  imported template/exercise seam used by Block Factory.
- `platform-portal/portal/seed_programming_engine.py` supplies the canonical
  competition lift identities and day-template vocabulary.
- `e2e/support/seed_database.py` and the existing Block Factory tests supply the
  realistic coach workflows: ordered catalogue assistance, automatic volume,
  explicit no assistance, and competition-oriented SBD exposure.

The durable, reviewable fixture is
`platform-portal/tests/fixtures/v79_golden_programmes.json`. Its catalogue rows
have explicit defaults and priorities so the test database cannot inherit
ordering from unrelated seed changes.

## Covered programme shapes

| Fixture | Protected shape |
| --- | --- |
| `low_accessory` | One deterministic automatic accessory per session |
| `moderate_accessory` | Two deterministic automatic accessories per session |
| `high_accessory_over_three` | Four ordered assistance rows per session, preserving a real high-volume manually authored shape beyond the automatic maximum |
| `zero_assistance` | No assistance remains authoritative even with high volume selected and eligible automatic catalogue rows present |
| `competition_oriented` | Three ordered SBD lift slots with peaking sets, reps, and RPE |
| `manual_pinned_assistance` | Coach selection order, round-robin placement, catalogue defaults, and `coach_selected` provenance |

The high-volume fixture deliberately uses pinned rows. Automatic selection still
has its existing maximum of three per session; proving a programme with more than
three assistance rows must not silently truncate does not alter that policy.

## Structural contract

`test_v79_golden_programmes.py` previews and accepts every fixture, expires the
SQLAlchemy identity map, reloads the block, and checks:

- session count and programme order;
- lift-slot count, position, family, and order;
- main-lift exercise identity and order;
- assistance count, identity, and order independently of lift slots;
- contiguous prescription positions;
- sets, reps, and RPE for main and assistance prescriptions;
- generated versus coach-selected provenance;
- assistance is not attached to a lift slot;
- explicit no assistance produces no assistance prescriptions; and
- the corpus itself retains all six required representative shapes, including a
  session with more than three assistance exercises.

This contract catches structural drift while avoiding brittle full-page and
full-object snapshots.

## Running the evidence

From `platform-portal`:

```bash
python -m pytest tests/test_v79_golden_programmes.py -q
```

For the adjacent Block Factory compatibility suite:

```bash
python -m pytest tests/test_v79_golden_programmes.py \
  tests/test_block_factory_v2.py tests/test_block_factory_v3.py \
  tests/test_programming_templates.py -q
```

When a deliberate programming-policy change modifies structure, update the
fixture and assertions together and record the coaching decision in the change.
Do not regenerate snapshots from current output without reviewing each ordered
field.
