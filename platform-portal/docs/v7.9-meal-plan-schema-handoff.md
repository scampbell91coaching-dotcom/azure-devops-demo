# V7.9 meal-plan schema handoff

This change deliberately adds no SQLAlchemy models or Alembic revision. Apply the following additions in one migration **after the macro-prescription branch is integrated**, using that branch's actual prescription table and revision key. Do not create a parallel prescription table.

## Contract audit

`MacroPrescription` is the authoritative coach-authored target; check-in target columns remain historical observations. V7.9 adds a positive `revision` to its schema-independent contract. A meal-plan publication copies prescription id, revision, and all five targets. `FoodSnapshot` similarly carries a catalogue food id plus facts revision and copied label facts. Neither identifier is dereferenced when reading a published assignment.

The repository boundary in `portal/services/meal_plans.py` exchanges immutable domain objects only. The in-memory adapter makes application and UI tests runnable before persistence exists.

## Exact migration additions

Use UUID primary keys unless the integrated macro branch establishes another project-wide convention. Use timezone-aware timestamps, `numeric(10,3)` for portions/macros, `numeric(10,1)` for calories, and date columns for effective periods.

- `meal_plan_templates`: `id`, `coach_id` FK users, `name`, `notes`, `status` (`draft|published|archived`), `current_revision` positive integer, `created_at`, `updated_at`; unique `(coach_id, name)` where not archived.
- `meal_plan_template_revisions`: `id`, `template_id` FK, `revision`, `payload_json`, `created_by` FK users, `created_at`; unique `(template_id, revision)`. `payload_json` is the immutable serialized days/meals/items/substitutions contract. It includes every day/meal position and note, portion, food id/facts revision/name/reference amount/unit/five facts, and substitution replacement. Do not update published rows.
- `meal_plan_assignments`: `id`, `athlete_id` FK athletes, `template_id` FK, `template_revision_id` FK, `effective_from`, nullable `effective_until`, `published_by` FK users, `published_at`, nullable `publication_override_reason`, tolerance columns for all five macros, `prescription_id` FK to the integrated macro table, `prescription_revision`, copied target columns for calories/protein/carbohydrate/fat/fibre, and immutable `snapshot_json` containing the complete published revision. Index `(athlete_id, effective_from, effective_until)`.
- Add a PostgreSQL exclusion constraint preventing overlapping inclusive date ranges per athlete for live assignments (`daterange(effective_from, coalesce(effective_until, 'infinity'), '[]') WITH &&`). For SQLite test/dev parity, enforce the same rule transactionally in the adapter.

If normalized editing is required instead of editing `payload_json`, add draft-only `meal_plan_days`, `meal_plan_meals`, `meal_plan_items`, and `meal_plan_substitutions`, each owned by `template_revision_id`, with unique parent/position and stable-key constraints. Publication must still write one complete immutable `snapshot_json`; athlete reads must never join the mutable catalogue or draft tables.

## Repository adapter requirements

Implement the existing `MealPlanRepository` protocol. `save_draft` must compare `expected_revision` in the update predicate. `add_assignment` must insert the snapshot and overlap-check in one transaction. Hydration must validate the domain rather than leaking ORM rows. Food selection queries must be restricted to active coach-curated catalogue rows; there is no external/branded-food ingestion in MVP.

Current assignment lookup and any athlete action call the nutrition entitlement policy. Assignment history lookup does not. Revoking service therefore hides current delivery and prevents new publication/actions without erasing the record that was previously delivered.

## Explicit exclusions

No allergy, disease, pregnancy, eating-disorder, therapeutic diet, supplement, or other medical decision logic is represented. The service calculates coach-entered portions and reconciliation only; it never optimizes portions or changes nutrition autonomously.
