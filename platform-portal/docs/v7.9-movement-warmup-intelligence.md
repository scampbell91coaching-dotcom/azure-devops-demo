# V7.9 movement-needs warm-up intelligence

V7.9 connects existing athlete-state coaching rules to existing versioned
warm-up protocols. The output is an explainable shortlist on the session editor,
not an assignment and not a rehabilitation plan. A coach must press **Accept and
assign** before the normal `WarmupAssignment` record is created.

## Deterministic contract

The service only considers rules already matched by `coaching_rules.py`, then
requires the session to contain the same lift family and an exactly keyed,
coach-authored protocol. It never searches drill names or invents content.

| Observation/rule | Required protocol stable key |
|---|---|
| Repeated squat hip shift | `squat-hip-shift-preparation` |
| Repeated squat heel-pressure loss | `squat-heel-pressure-preparation` |
| Active squat constraint | `squat-constraint-preparation` |
| Active bench constraint | `bench-constraint-preparation` |
| Active deadlift constraint | `deadlift-constraint-preparation` |

The newest version of the exact protocol key is offered. Contrary evidence,
insufficient observations, a wrong-lift session, a missing protocol, or an
already assigned version produces no candidate. Ordering is stable by lift,
rule, protocol key, descending protocol version, then source IDs.

## Audit and authority

The candidate displays its reason, rule ID, coaching-rule generator version,
protocol version, source observation/constraint references, and any active coach
override. Acceptance re-evaluates the candidate server-side and stores those
fields, plus mapping version `movement-warmup-mapping-v1`, as compact JSON in the
existing assignment `reason`. No migration is required.

Manual assignments and manual step overrides are unchanged. Opening an athlete
session still snapshots the accepted warm-up through the existing resolver.
Candidate generation never mutates programming.

These mappings express only a coach-reviewable preparation option. They do not
diagnose why movement occurred, determine exercise safety, prescribe treatment,
or autonomously prescribe rehabilitation.

## Accessory seam

`MovementNeed` is a typed, non-diagnostic representation of the matched rule,
lift, sources, version, and reason. `AccessoryCandidateProvider` defines an
optional provider boundary for a later accessory shortlist. Block Factory is
not imported or changed; adopting that seam remains a separate coach-reviewed
increment.
