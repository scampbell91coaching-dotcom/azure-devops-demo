# V7.4 persisted session warm-ups

V7.4 connects the pure `portal.services.warmup_plans` concepts to the existing
programming and athlete-session workflow without representing warm-ups as work-set
prescriptions.

## Persistence model

- `warmup_protocols` identifies a reusable protocol by `stable_key` and immutable
  integer `version`. `warmup_protocol_steps` stores its typed, ordered instructions.
- `warmup_assignments` pins one protocol version to the athlete owned by a specific
  training session. The coach, reason, and assignment time retain provenance.
- `warmup_overrides` is an append-only record of coach removals or additions. Every
  override requires a reason. It does not mutate the source protocol.
- `warmup_plan_snapshots` and `warmup_plan_snapshot_steps` copy the resolved order,
  dosage, notes, source key, and source version when the athlete first opens the
  session. The unique athlete/session boundary makes resolution idempotent.

Protocol steps and warm-up snapshots remain separate from
`exercise_prescriptions`, `training_session_logs`, and `training_set_results`.
Consequently they cannot inflate volume or alter existing set logging. Foreign keys
to assignments, overrides, snapshots, and their programmed sessions use `RESTRICT`;
only protocol children and snapshot children cascade. This protects programming and
athlete history.

## Lifecycle and authorization

The coach can create-and-assign a reusable plan, assign an existing pinned version,
remove a resolved step, or append a manual step from the session editor. Manual
changes require an audit reason. A coach preview reads current assignment and
override events.

The athlete route already enforces that the active block belongs to the signed-in
athlete. It creates or reloads the immutable snapshot and renders the ordered warm-up
after session notes and before work sets. Once that snapshot exists, coach mutation
returns HTTP 409 so an in-progress or completed session never drifts.

This release intentionally does not infer loads, generate warm-ups, capture warm-up
completion, or provide medical/injury guidance.

## Migration

Alembic revision `0014_warmup_integration` follows the inspected single head
`0013_accessory_intelligence`. It creates only new tables and requires no backfill.
Downgrade removes only those six tables in reverse dependency order.
